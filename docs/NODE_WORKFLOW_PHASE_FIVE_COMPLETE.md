# Phase 5 closeout — supported workflow authoring

October 21, 2026. **Phase 5 and the original five-phase node-workflow milestone are complete within the trusted built-in scope.** This final pass closes the supported node/source configuration, visual editing, grouping and preset lifecycle gaps. Earlier evidence remains in [pass 1](NODE_WORKFLOW_PHASE_FIVE.md), [pass 2](NODE_WORKFLOW_PHASE_FIVE_PASS_TWO.md) and [pass 3](NODE_WORKFLOW_PHASE_FIVE_PASS_THREE.md).

## Author workflow

Open **Workflows → Edit workflow presets**. Choose an opening, continuation or latest-rewrite template and bind a saved source. The existing typed list editor remains fully available. **Show workflow canvas** adds selectable cards, typed input/output buttons and explicit connection creation. A separate checkbox authorizes replacing an existing input connection. Structural and execution errors remain visible before saving/running.

Canvas cards support pointer dragging and keyboard arrow movement. Four built-in presentation groups — sources/models, prose, world updates/checks and acceptance/recovery — can collapse independently. These groups and positions are browser-local layout, separate from executable definitions, canon, saved preset revisions and passage metadata. Selecting a card focuses its configuration heading. Narrow screens scroll inside the canvas; the page remains bounded and the list/port editor supplies the alternative. Arbitrary executable subgraph groups are outside this milestone.

Select a **model node** to enter a model name on the existing configured text connection, a narration-temperature override or a lower output-token ceiling. Blank values inherit Settings. Route prose, extraction/repair or review stages together using explicit buttons. Matching configuration is required between request preflight and its consuming narration/expansion or extraction/repair stages. This prevents an earlier request budget/schema from being consumed with different settings. Addresses and credentials still resolve exclusively from server Settings; no provider discovery, automatic fallback, context-window increase or default extra call is added. Effects and inventory review keep their existing fixed low-temperature behavior. Provider availability is established by the actual explicit request, rather than by an extra automatic probe.

Select the **source node** to add up to 250 visible record references. A small read-only endpoint returns only IDs, names and record kinds, excluding prose, hidden lore and copied record bodies. Search shows at most 120 matching candidates while selected references remain removable. Reload failures preserve the draft; changing a source explicitly clears its old workflow references. The server repeats source/revision, visibility and reference-limit checks before a fresh passage job/provider call and under the source job lock. Effects-only recovery uses corrected current facts; old narration hints remain provenance, and unused narration-only model nodes/budgets are skipped. Rewrites resolve references against their valid pre-event world. References are ephemeral preparation hints using the existing scoping machinery; they do not change saved scene briefs, place cast members, grant viewpoint knowledge or authorize deleting omitted canon. Canon, pins, preferences and required evidence remain authoritative.

Select **Choose repair branch** to choose either the existing one automatic repair or **Retain prose for explicit review**. The latter adds one trusted blocked-output connection while preserving every mandatory stage/check/save connection. Invalid structured updates or failed inventory review then retain prose without the automatic repair call. Explicit effects-only retries and reviewed atomic acceptance still work, including after the preset is archived. Unsupported check rewiring, extra provider stages and cycles remain nonexecutable drafts; final server validation cannot be disconnected.

## Presets, checkpoints and compatibility

Presets can be copied, archived/restored and inspected through saved revisions. Opening a historical revision creates an unsaved independent copy; it cannot overwrite the current version. Archive/restore use revision checks and idempotent receipts. Archived definitions leave fresh passage selectors and cannot start new operations; immutable versions, completed request replay, in-flight work, supported recovery and passage checkpoints retain their original definitions. The library is bounded at 200 presets including archived entries; revision browsing lists the latest 100 while earlier immutable revisions remain stored/addressable. Archiving is reversible and does not erase definitions needed by history.

Version-1 definitions gain optional strict built-in node configuration. Existing definitions and defaults remain valid. Portable preset export detaches source bindings and source-specific reference IDs, retaining supported model/branch settings. Unsupported URLs, API-key fields, scripts or copied canon cannot enter node configuration. Older app versions may reject the new optional configuration/ports and must be updated to execute these presets.

Accepted passages continue to checkpoint their exact workflow definitions and historical world/context/prose in the canonical transaction. Model provenance now also records the resolved public settings for every executed model node, with the actual narration model identified separately. Original narration and accepted-check workflows remain distinct during recovery. No private connection address/key, raw prompt or provider response is added to portable metadata. Checkpoint ZIP round trips, historical images, source deletion and independent past-passage forks remain covered. New runs use current configured connection settings plus explicit supported node overrides; no global setting is silently restored.

Authoring makes zero provider calls. The configured failure path makes narration/extraction once; the explicit retry makes extraction/review without renarration. All providers and stories are controlled isolated fixtures. Normal libraries/settings, historical fixture reports and release ZIPs are untouched; this is not new live-model quality or generation-speed evidence.

## Scope after closeout

Further work is a separate follow-up rather than an unfinished Phase 5 gate: multiple independent API profiles, provider discovery/fallback, arbitrary third-party nodes/scripts, unrestricted loops, executable subgraph groups, parallel scheduling, general artifact caching/replay, cross-fork deduplication, long-history import/compaction benchmarks, richer lineage/alternative browsing and deliberate checkpoint refresh after manual edits. Older passages without trustworthy checkpoints remain unavailable for historical world reconstruction. Sustained-model quality and entity/context scoping remain evaluation priorities, without an automatic context/call increase.
