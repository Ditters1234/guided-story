# Story-linked illustrations

Implemented October 17, 2026. The studio extends the existing ComfyUI runner and shared media library; no new packages or services were added.

## Using it

1. Choose **Illustrate this passage**, **Create portrait** in a cast Photobook, **Generate a picture** in Gallery, or the **Illustrations** navigation tab.
2. Choose portrait/bust, full body, or scene/group framing; select depicted characters, places/objects, and optionally a source passage or parent picture. **Landscape orientation** at the top of the generator swaps this shot's width/height (for example, 512 × 640 becomes 640 × 512). Turn it off to return to portrait; saved ComfyUI defaults and shot framing are unchanged. The canvas size updates immediately. Both size bindings are required; square dimensions remain square.
3. Saved visual identities load automatically. Use **Suggest visual details from story** / **Refresh prompt from story** for established facts and the selected moment, or **Fill missing details** to propose unspecified visible features such as eye color. Suggestions change this image only. Review them before choosing **Remember visual identity** to save them to a cast member.
   Each cast member also has **Shot choices**: left/center/right placement, foreground/middle/background depth, and gaze at the camera, away from it, or at another depicted character. Automatic leaves that choice unspecified. Detail switches select face/hair/eyes, build, clothing, accessories and distinctive details/condition. They affect the prompt immediately without a model call and do not erase the editable values. New portraits start with build details off; lower-body clothing and footwear remain outside the crop. Older saved compositions retain their previous inclusion behavior. Free-text scene/pose descriptions remain authored text; review them if they repeat an excluded feature or conflict with a staging choice.
4. Review the resolved prompt. **Copy resolved prompt** copies the exact current positive prompt; a finished generation's **Copy captured prompt** copies the prompt sent for that generation. Copy success is shown beside the control; failures also appear in the bottom Errors panel. Portraits exclude lower-body and footwear variables. Group members remain in separate named blocks; selected place/item blocks include their names and descriptions. For an older passage, check its action/outfit against the current facts before generating.
5. Select a workflow and check its bindings. Defaults come from Settings → ComfyUI. Request overrides include dimensions, steps, CFG, seed and mappings. **Suggest workflow bindings** handles familiar nodes; custom graphs need explicit mappings. Import API workflows through Settings.
6. Generate. With a text model configured, unprepared/stale story details refresh first by default. Review them beforehand with **Refresh prompt from story**, or turn off **Refresh stale story details before generating** to use the current fields. ComfyUI work continues while you read; Generations retains status, errors, seeds and full-size previews. Return after restart to reconcile the original job without resubmission.
7. Caption and **Keep illustration**, choosing canonical/experimental and optionally selecting a portrait as the current avatar. The same asset appears in all depicted cast members' photobooks, and previous pictures remain available.

When a source passage is selected, **Which part of the scene? (optional)** lets you describe one beat or paste a short excerpt, such as “Mira hands over her jacket, before the airlock opens.” Each source paragraph also offers **Use this moment**, which copies that paragraph exactly into the field without calling a model. Paragraphs longer than the 2,000-character limit require a shorter pasted excerpt; moment controls are disabled while a complete prompt override is active. **Clear selected moment** clears only this selection. Leave it blank for automatic moment selection. **Refresh prompt from story** uses that focus to prepare action, poses, setting and clothing at the chosen moment; automatic preparation before Generate does the same. No model call occurs merely from choosing or clearing a moment.

While an older scene remains filled in, changing the source passage or selected moment stays pending through unrelated appearance/background edits, Fill missing details and Remember visual identity. Refresh the full shot, or intentionally write **Visible scene / action** to accept the new source as a manual composition. Fill missing details can prepare a previously blank scene, but it does not replace an older nonempty scene. With automatic refresh off, refresh explicitly or write the intended scene before generating. A complete prompt override remains authoritative. Reference art ignores a hidden passage focus.

The focus is retained in device drafts, reused compositions, accepted picture provenance and story archives. It is an image instruction, not a canonical story edit. With no prepared scene, a source-linked focus can supply the scene text directly; once a scene has been prepared or manually written, the resolver keeps that visible scene instead of appending selection instructions.

**Reuse shot / new variation** copies the composition and uses a new seed. Gallery's **Generate a variation** also links the parent image and reuses its stored composition when available. This is text-to-image variation: identity-reference images are not yet sent into a workflow. Review current facts and the selected workflow before generating again.

Last-shot drafts/settings are cached on this device per story. Accepted images and metadata are saved server-side and exported. Source-free portraits are reference art; changing a shot never edits canonical clothing, inventory or relationships. Remember visual identity is a separate explicit cast edit. Shot wardrobe, injuries and supplemental notes do not silently overwrite the shared character profile.

## Shared character profile

Character creation, narration, cast editors and pictures now use the same normalized [character profile](CHARACTER_PROFILES.md). Actual and apparent age, gender and presentation are distinct; wardrobe is stored by body region, injuries are current condition, and appearance/outfit summaries are derived. Default picture prompts use apparent age/presentation, and supplemental visible/clothing notes have editable shot fields. Older-passage preparation omits present-day clothing/injuries as historical evidence. Remembering visible traits preserves established actual identity and off-frame markings.

## Visual identity and natural-language prompts

New shots default to **Natural language · Krea / Z-Image**. The deterministic compiler combines a concrete moment, crop/cast count, separately named character descriptions, visible wardrobe/actions, environment, camera/composition, lighting/palette and art direction. Enabled identity detail groups are included, alongside visible age (apparent age before chronological age), visible presentation, species/form, skin, build, face, hair, eyes and distinctive features. Actual identity remains saved separately. Lower-body wardrobe and footwear are omitted from portraits. The preview and server use the same compiler; there is no hidden second prompt rewrite after review. Framing uses medium-neutral words such as full-body view and environment view. The compiler does not inject illustration, painting or rendering language; only explicit art direction/custom text requests a medium. The text assistant is instructed to keep style out of scene/background/subject fields, since art direction is compiled separately. The former exact stock full-body template is normalized on settings load, draft restore/reuse and prompt resolution, while custom templates and historical saved prompts remain unchanged. Refresh older generated scene details once if they contain a previous style.

**Shot choices** select which supplied detail groups reach both natural-language and template prompts. Distinctive details covers markings, supplemental visible features and injuries/condition; clothing covers the three clothing regions and supplemental outfit notes. Placement, depth and gaze compile into named sentences so group members keep separate staging. They are preserved through profile filling, both suggestion modes, device drafts, captured compositions, accepted image provenance, archives and shot reuse. They do not make story details stale or trigger another text call. A newly selected passage or moment remains stale when only these controls change. Complete prompt overrides remain authoritative. Gaze targets must be another depicted cast member; removing the target in the editor resets that gaze to Automatic.

Selected places and objects use their reusable **Visual description** when filled, falling back to the ordinary description for existing records. Visual preparation uses the same visual description. Narrative notes and image descriptions can therefore stay separate without introducing another model pass.

**Fill missing details** can invent undecided visible features as image-only proposals; the server preserves all nonempty fields even if the model tries to replace them. It does not invent age/gender from names or content flags. Story refresh preserves entered identity traits but updates scene/background, clothing, pose and expression. **Fill blanks from saved profiles** uses saved structured details without a model call. Legacy freeform descriptions are available to the assistant; they are not copied wholesale into the face field. Without granular physical details, natural-language prompts can fall back to the saved appearance, filtering off-frame wardrobe for a portrait.

**Remember visual identity** stores the reviewed identity fields only. Wardrobe, pose and expression remain shot-specific. Visual identities are also editable in Records → Cast and new-story setup, included in narrator context, saved/exported with canon, and can receive evidence-backed partial updates after explicit narrated appearance changes. Appearance pins protect these updates. New-story design requests a visual profile for each generated character. No NSFW remains independent of age and gender.

This follows [Krea's official natural-language prompting guidance](https://github.com/krea-ai/krea-2/blob/main/docs/prompting.md). Krea 2 and [Z-Image](https://github.com/Tongyi-MAI/Z-Image) are separate model families selected by a ComfyUI workflow, not consecutive processing stages. The included graph loads Krea 2. Workflows remain selectable; the app does not change sampler/CFG assumptions or invent unsupported negative/reference bindings for another model. Detailed text improves the input contract but does not guarantee identical faces across generations; reference-image execution remains a follow-up.

## Prompt refresh

The preview recombines current shot/template fields automatically. Refresh from story is a separate text-model operation that updates scene/background and shot-specific cast fields using the selected passage and saved facts, preserving entered identity traits. The source freshness indicator follows passage text, selected cast/objects/places, framing and content preferences; unrelated saves, seed/workflow changes and template/art-style edits do not force another text call.

After a source has been prepared, editing scene/background/cast fields explicitly makes the current shot manual: Generate preserves those fields. Unrelated edits cannot accept a newly selected passage or moment; only a full story refresh or an intentional **Visible scene / action** edit does that. Captured-shot reuse/variations retain their composition. Use Refresh prompt from story when you want the model to replace them. Complete one-image overrides take precedence and disable story refresh; an empty enabled override must be filled or turned off. Without a configured text model, manually entered shots still generate normally. These controls do not change saved Settings or historical image prompts.

Generate resolves the current fields again at submission, and the server resolves the same draft against the expected story revision. The resulting prompt is captured with the queued job and applied to the workflow's actual positive-prompt binding. Failed/cancelled preparation stops before ComfyUI submission and preserves prior details. **Cancel prompt refresh** also requests cancellation of its tracked text job. Freshness/manual mode and the automatic-refresh choice are retained with the device's shot draft.

## Templates and preferences

Settings → Prompts provides portrait/full-body defaults and a **Story scene / group template** for the studio's **Custom prompt template** mode. The single-subject Scene template remains available for Settings tests. Templates can be overridden in the studio without changing defaults. Existing captured shots retain their prompt mode; new compositions use natural language.

The studio supports `{{art.style}}`, `{{image.scene}}`, `{{image.background}}`, `{{image.composition}}`, `{{image.lighting}}`, granular `{{subject.…}}` variables (including visible age/gender, explicit actual_age/apparent_age/presentation/gender_identity, species/skin/build/distinctive, injuries, appearance_notes and outfit_notes) and `{{subjects}}` for all selected subjects in separate named descriptions. Singular variables refer to the first cast member shown in the editor. Missing identity variables are appended to single-character templates so older templates do not drop age, gender or eyes. Multi-person templates require `{{subjects}}`, unless using an explicit complete prompt override. Unknown variables are errors in template mode; unused templates are ignored in natural-language mode. Templates cannot execute code.

Templates also support `{{subject.position}}`, `{{subject.depth}}` and `{{subject.gaze}}`. Values are ready-to-use phrases, such as “on the left side of the image” and “looking at Mira Sol.” Missing staging variables are appended to single-character templates, while `{{subjects}}` already contains each person's staging. Unchecked detail groups resolve to empty strings in granular variables and are excluded from appended identity/notes.

The requested nonsexual setting, story adult-content preference and each character's No NSFW preference are assembled server-side and snapshotted. Complete prompt overrides still receive the applicable instructions. The model cannot toggle these preferences. No content classifier, age inference, or automatic provider switching was added. A negative prompt requires a mapped negative input; the supplied graph uses zeroed conditioning, so leave its negative field empty unless adapting the graph.

The studio's **Nonsexual, fully clothed image** checkbox is checked and disabled while Settings → Story → Allow adult content is off; the help text explains that requirement. When the story allows adult content, the image checkbox becomes optional. Selected cast members with No NSFW still receive their individual instructions, and the studio names them beside the control. To remove the automatic whole-image and individual nonsexual instructions, allow adult content for the story, turn off No NSFW only for the intended depicted profiles in Records → Cast, and turn off the image checkbox. Existing wardrobe descriptions and explicit story content notes still apply. Unit/check/build and illustration browser coverage pass, including the exact queued ComfyUI request with the automatic instruction absent when permitted. Updated production ZIP verification is a separate pending checkpoint in [Project status](PROJECT_STATUS.md).

## Durability and source history

Unmapped studio controls are disabled and retain the workflow's own values. If no seed input is mapped, the app reports a workflow-defined seed and stores `null`, rather than claiming that an unused random seed controlled the output.

Story images use `story-illustration` jobs and a separate `illustrations:<storyId>` lock. Text narration can proceed independently of one active image job. Settings tests keep their own queue/storage. Optional visual preparation is a cancellable text job, not a canon transaction.

Queueing captures the passage ID/hash/title/chapter/revision, depicted IDs, appearance/outfit snapshots, editable shot fields, resolved prompts, workflow/graph/bindings, seed/settings and effective content preferences. Prompt IDs and original ComfyUI endpoints survive restart. If submission was interrupted before a prompt ID was saved, inspect ComfyUI before requesting another image; the app does not automatically replay it.

Previews live in `data/<instance>/illustration-previews`; Settings uses `test-images`. Clearing Settings previews cannot remove story-job previews. Discarding a finished preview leaves accepted story images intact and does not interrupt the shared ComfyUI server.

Acceptance validates bytes through Sharp, stores immutable originals/thumbnails and commits metadata/optional portrait selection with a revision check. Captured facts remain accurate when a character changes during generation. If the source passage was revised, the image is saved as superseded and is not selected as a current portrait. Repeated acceptance of one job/output returns its existing asset. Concurrent edits cannot overwrite newer story state; refresh and retry using the retained preview.

ZIPs carry accepted originals, associations, source labels, snapshots, composition/prompts, graph/bindings and generation identity. Credentials, pending jobs, device drafts and unaccepted previews are excluded. Inspect jobs and actual requests in Dev.

## Interfaces and checks

- `GET/POST /api/stories/:id/illustrations`: list / submit.
- `POST .../illustrations/prepare`: optional text suggestions with revision checks.
- `GET/DELETE .../illustrations/:jobId`: reconcile / discard a finished preview.
- `GET .../:jobId/image?index=N`: scoped preview bytes. Other stories and Settings test URLs cannot serve this job.
- `POST .../:jobId/accept`: caption/status, revision check, optional portrait selection.

`tests/illustrations.test.ts` covers framing, groups, preferences, source freshness, invalid references, frozen facts, atomic portrait selection, replay, ZIP portability and delayed supersession. `node scripts/illustration-smoke.mjs` adds isolated production UI/mock providers, explicit/source-triggered preparation, exact preview-to-workflow prompt checks, manual edits/overrides, preparation failure/cancellation without image submission, photobooks, restart without duplicate submission, scoped previews, archives and 320px layout.

`node --import tsx scripts/illustration-live-smoke.mjs` uses saved play connections with isolated saves. The actual local model prepared a portrait; ComfyUI generated a 512×640 portrait and two-person scene at four steps, about 12 seconds each in the earlier check. The October 19 review additionally exercised real fill-missing with entered age/gender/hair, proposed hazel eyes/complexion/features, and generated a natural-language portrait and two-person scene at eight steps (61 and 40 seconds). Both were visually inspected, saved, integrity-checked and round-tripped through ZIP. Normal play data/settings were untouched; proof/images are in ignored `test-results/illustration-live*`. Existing media and restart walkthroughs also pass.

Automatic illustrations after every passage, reference-image bindings, inpainting and richer saved workflow profiles remain separate follow-ups.
